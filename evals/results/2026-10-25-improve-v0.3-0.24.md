# The blind v0.3 run again, after the fixes: safer, less complete

Date: 24 and 25 October 2026. Skills: this repository from release 0.19.0, taking in 0.20.0 to 0.24.0 and this
run's own fixes as they were released. Edit setting: `conservative`. Model: Claude Opus 5.5 for the
coordinator, every stage agent, the simulated readers and referees, and the independent re-check. Reviewers
of the result: fresh Claude Opus 5.5 agents and Codex (`gpt-5.6-sol`, reasoning effort high), each in an empty
folder outside the manuscript's repository.

## What was run

The full manuscript-improve workflow on the same v0.3 draft as the 2026-10-22 run
([2026-10-22-improve-v0.3-blind.md](2026-10-22-improve-v0.3-blind.md)), under the same blind conditions. It
ran integrity, references, reporting, figures, policy fit and journal selection, each with an addendum after
the journals were named. Then came three simulated referees with a defence and adjudication, and a revise and
prose edit that applied the review stages' proposals. Deslop followed, then the story stage with the project's
six readers, each a fresh agent, and journal adaptation for what the shortlisted venues share. The run ended
with the dashboard, the corrected version, its verification and the independent re-check. The run, its
dashboard and the comparisons stay with the manuscript project
(`just-dna-lite/docs/manuscript/v0.3/reviews/2026-10-24-blind-improve-0.19/`); they quote the unpublished
draft.

## Results

- 99 distinct problems confirmed (2 blockers, 25 major, 46 minor, 26 optional), 9 candidates, 52 dismissed
  flags; 53 records from several stages merged into 30.
- 84 edits applied in the working copy, each recorded with its reason and finding; the corrected version adds
  12 proposals and holds 90, of which 60 had already been applied under another number.
- 13 decisions and 7 questions for the authors, against 72 questions in the 2026-10-22 run.
- The independent re-check judged 36 problems fully fixed, 24 partly, 31 open, 1 worse and 7 not checkable,
  and found 9 problems the edits introduced. In response, two proposals were held and two slips fixed with
  recorded edits. Corrections a confirmed finding asked for were kept.

## Quality: what fresh reviewers made of it

The same two briefs as the baseline ("which version would you rather read and submit", and "did the revision
keep the paper") were given to one Claude and one Codex reviewer for each comparison.

| | 0.12.1 run | This run |
|---|---|---|
| Blind, corrected vs draft (Claude / Codex) | corrected preferred, high / high | the same, with the same scores |
| Serious damage (Claude / Codex) | 3 / 8 | 1 / 5 |
| Changes the authors would reject (Claude / Codex) | 30% / 35% | 20% / 30% |
| Authors' voice kept (Claude / Codex) | yes / no | yes / yes |
| Head to head, this run against the 0.12.1 run | | 0.12.1 preferred by both, medium confidence |

The run did less damage and kept the authors' voice. Codex, which found the voice lost in the 0.12.1 run,
now finds it kept. But both reviewers, reading the two corrected versions side by side in either order,
prefer the 0.12.1 version for its substance. It corrected more from the code: a feature's use of outside
services, what a warm run reuses, how ancestry is inferred, the closest competing tool. This run found most
of those problems but left them as decisions and questions for the authors.

Against the same 125 items (the human referee's comments and tracked edits, the authors' later fixes, a

|---|---:|---|---|
| All | 125 | 52 / 24 / 49 | 42 / 31 / 52 |
| Substantive | 80 | 46 / 19 / 15 | 39 / 23 / 18 |
| Referee's comments, substantive | 25 | 8 / 10 / 7 | 9 / 12 / 4 |

This run's counts include four bibliography problems that the reference check fixed with routine corrections

caught more of the referee's substantive comments and fewer of the authors' own later fixes. Most of those
are places where the text disagrees with the code, which the 0.12.1 run's integrity check found and this
one's did not.

## What the run taught the skills

Fixed and released during the run, and just after it:

- The reader brief's example answers named the paper's own sections and figures, and readers copy that
  format; the template now uses neutral placeholders (bbb208b).
- collect refused proposals with `"comment": null`, which five stages wrote (24a7de0).
- collect replayed recorded edits skill by skill, and manuscript-improve comes first in the run manifest, so
  the coordinator's follow-up edit after the re-check broke the replay and revise.py's undo order; changes now
  carry their time and replay in the order they were recorded. The re-check refused the `null` quote its own
  brief asks for with an unchecked verdict (8897a1e).
- The claim guard read "hard disk drive" as a cause, a negated "does not establish" as a claim of proof, and
  the title of a cited work in the reference list as the authors' claim (f7aa380).
- From the quality comparison: a fact the project's own code, configuration, data or run records settle is
  checked there and corrected, not left to the authors. When the corrected version reads worse, style and story
  edits are dropped, but a correction a confirmed finding asked for is kept and its sentence split or
  tightened. On a re-check failure such a correction is kept, a slip it left is fixed, and what remains is
  listed (39ca900).

- `runs.py validate --final` required every consequential edit to be attested as shown in chat, so a run whose
  stages are agents and whose authors are away failed on that alone (43 edits here). On the authors' decision,
  it now accepts an edit the newest rendered dashboard shows unchanged, and lists it under
  `shown_in_dashboard`; nothing is attested as shown in chat. The run then validates.

Found, not changed:

- Review-stage proposals that the revise stage applied keep their "proposed" status, so the coordinator holds
  them to keep them from being applied twice, and the dashboard lists them as held, beside the real decisions.
- The smell check counts an author's participle tail as added when an edit only moved the citation in front
  of it.
- Journal selection's "Adapt now: one version serves every venue" lists section structures that differ
  between the venues; journal adaptation correctly did not restructure the paper, but the heading says more
  than the list supports.
- Registry-settled reference corrections are applied without a finding, so the dashboard and a coverage grader
  count them as edits, not as problems found.
- A simulated faithfulness reviewer valued a line as the authors' voice that the human referee had marked as
  machine-like phrasing; the human reading was kept (the catalogue entry stays).

## Limits

- One reviewer of each model per comparison; a medium-confidence preference rests on one reading.
- The 0.12.1 run used its own settings; this run used `conservative`. Part of the difference in substance is
  the setting, not the release.
- The re-check read the build before the last two holds and two follow-up edits; the dashboard says so.
- The rendered dashboard was not opened in a browser in this session.
